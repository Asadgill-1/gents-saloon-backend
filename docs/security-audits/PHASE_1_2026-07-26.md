## Evidence

- Backend locked checks passed: `uv lock --check`, Ruff lint/format, strict mypy, and `pip-audit` with no known vulnerabilities.
- Backend unit suite collected 54 tests and passed 46 with 8 isolated-database tests skipped by the normal suite.
- `scripts/test-database.ps1` rebuilt an isolated PostgreSQL database from all five migrations, passed the complete RLS matrix, and passed all 8 database-gated actor/onboarding/subscription/surface/export/offboarding tests.
- Shop dashboard `npm run check` passed lint, TypeScript, 6 tests, and a Next.js production build; `npm audit --audit-level=high` reported 0 vulnerabilities.
- Platform dashboard `npm run check` passed lint, TypeScript, 5 tests, and a Next.js production build; `npm audit --audit-level=high` reported 0 vulnerabilities.
- Built static bundles in both dashboards contained none of the checked backend secret names.
- Current-tree secret scanning produced only reviewed code-identifier false positives for parsing an authorization token and generating a random token. Full Git-history scans found no hard-coded credential files. The ignored owner scratch file was not printed.
- Static guards found no dangerous Python execution/deserialization, wildcard CORS, unverified JWT decode, browser token storage, raw HTML sink, permissive RLS policy, unsafe Celery serializer, mutable CI action, unsafe CI trigger, or client-prefixed backend secret.
- Redis rate limiting uses a fixed Lua program rather than dynamic input. It does not invoke Python `eval`; keys contain only a route class plus a SHA-256 actor/IP digest.
- JWT validation allowlists ES256/RS256 and verifies signature, issuer, audience, expiry, issued-at, not-before, and UUID subject before database authorization.
- Tenant and platform services recheck the actor inside short database transactions. Client business/shop/role claims are locators or ignored, never authorization.
- Subscription, onboarding, export, delivery, archive, receipt, reversal, and billing-mode mutations are idempotent and write append-only audit plus outbox records in the same transaction.
- Export archives use explicit dataset/column allowlists, redact credential-like audit fields, exclude bot/webhook/queue/storage/idempotency/outbox secrets, record schema version/size/SHA-256, and use opaque private-object keys.
- Worker claims use `FOR UPDATE SKIP LOCKED`, commit before archive/storage work, recover stale claims, and persist only safe failure codes.
- Offboarding freezes before export and requires explicit delivery confirmation before soft archive. It disables subject-scoped ownership/memberships, bot/public access, and tenant entitlement without hard deletion or cross-business revocation.
- Local migrations enforce legal export/offboarding state transitions, one open case per subject, processing metadata, object-deletion state, and worker indexes.
- Remote Supabase has 14 application tables, all RLS-enabled, with 0 application rows. All five Phase 1 migrations are applied.
- Remote Supabase Storage bucket `tenant-exports` is private, limited to 100 MB ZIP objects, and has no browser object policies.
- Remote Supabase Security Advisor reported 0 findings. Performance Advisor reported only unused-index INFO notices expected on the empty development schema and no missing foreign-key index finding.
- CI definitions have read-only permissions and immutable SHA-pinned actions; no `pull_request_target`, write permission, or untrusted action reference was found.
- `git diff --check` found no whitespace error; Windows line-ending conversion notices remain informational.
